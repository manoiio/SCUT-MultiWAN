## 已部署行为

- 保留原组播/广播注销与明确确认要求；无回复时最多进行三轮发现或
  对已发现交换机的定向注销。发现使用广播/组播路径，不回答 Identity
  或 MD5，不发送凭据。每轮重新检查真实 Portal 锁下的活动窗口，并
  遵守单调时钟、事务期限及停止信号。全部不确定仍保留账本并停止
  新登录，三轮不重复 claim 认证额度。
- 首次 UDP 心跳之后启动独立有界路由复核，最多六次、间隔 15 秒，
  开始期限为 180 秒。每次复核引擎 PID/starttime/exe/ready 一致性、
  路由时间守卫，继续使用真实 dualwan-refresh 公网验证及两次成功
  至少间隔 30 秒的恢复条件。不会认证、释放、覆盖静默或写会话。
- 系统日志写入 `/etc/scut-logs/system.log`，单文件约 2 MiB，轮转为
  `system.log.old`。RAM 环形区仍为 128 KiB，既有 logd PID 1622 保留。
  日志目录 700，文件 600；没有配置向外发送日志。
- `/etc/init.d/scut-reboot-watch` 启用为 S11，先于 S12log。新 boot ID
  出现时归档旧/当前日志尾部各最多 512 KiB，最多保留四份
  `previous-1.log` 到 `previous-4.log`；最近的为 previous-1。记录
  previous/next boot ID 和归档墙钟，校时偏差可用 uptime 对照。
- 每分钟记录 boot ID、uptime、可用内存、负载、温度；启动记录包含
  watchdog bootstatus。总持久日志约 8 MiB 加少量行及元数据。使用
  [OpenWrt logread 的文件轮转与同步写入机制](https://github.com/openwrt/ubox/blob/master/log/logread.c)。
  硬锁死、突然断电或来不及送达用户态的最后 panic 行仍可能缺失，
  不等于完整 crash dump，也不能补回这次重启前的日志。
