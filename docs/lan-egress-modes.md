# LAN 出口切换（2026-10-07 已部署）

在 LAN 内打开 [切换页面](http://192.168.1.1/cgi-bin/luci/admin/network/scut_lan)，登录原 LuCI 后进入「网络 → LAN 出口切换」。页面显示当前模式及就绪状态，三个按钮立即生效，不需要另点保存应用。当前已选择并持久保存**单有线出口**。

| 按钮 | LAN 互联网路径 | 故障行为 |
| --- | --- | --- |
| 三网聚合隧道 · VPS 出口 | 三条校园 WAN 的 MPTCP 子流 → 新 VPS；IPv4 实测出口 `58.252.223.164` | 初次连接不成功则保留原模式；已选隧道断线后等待恢复，不泄漏到校园直连 |
| 原三网出口 | IPv4 恢复原表 103，健康链路按连接分流 | 原健康路由维护自动移除故障链路；当前 IPv6 仅有线可用 |
| 单有线出口 | LAN 只走有线 WAN；IPv4 实测出口 `110.64.88.149` | 有线不可用时等待恢复，不自动切无线 |

作用于主 LAN `br-lan` 的互联网流量，包含 TCP、UDP、ICMP 和 IPv6。LAN 内部通信、路由器管理保留；路由器自身的认证、无线维护和隧道底层连接继续按各自原规则运行。局域网以外的私网目标不经 VPS 公网隧道。显式 HTTP/SOCKS5 代理 `192.168.1.1:1088` 也跟随选择，切换时关闭其旧连接；其他已有下载、游戏和通话可能需要重连。

也可通过 SSH 切换或检查：

```sh
ssh root@192.168.1.1 'scut-lan-mode set tunnel'
ssh root@192.168.1.1 'scut-lan-mode set multi'
ssh root@192.168.1.1 'scut-lan-mode set wired'
ssh root@192.168.1.1 'scut-lan-mode status'
```

模式文件 `/etc/scut-lan/mode` 权限 600；开机服务 `S99scut-lan-mode` 恢复选择，5 秒健康检查更新专用默认路由。已实际重启该服务并确认恢复单有线，尚未通过整机冷启动验证。切换不注销、重新认证、重启无线或修改已有校园会话记录。

## 实现范围

新全协议 IP 隧道使用独立端口 57502、TUN `scut-lan`、MTU 1400，TLS 1.3 认证及 MPTCP，保留旧端口 57501 的 Web 代理。令牌、证书私钥及实际私有配置只在设备上，未下载或纳入仓库。新 VPS 是生产出口，香港、sglg 不转发生产流量。

LAN 专用 IPv4/IPv6 表 106、优先级 90 仍按 `iif br-lan` 匹配；原表 103 不改变。1088 代理直接模式的套接字用独立标记选择表 103/106。独立 nft 表控制 LAN 转发、DNS 和 NAT；模式切换短暂阻断外部转发，保留管理访问。单有线/隧道模式的 LAN DNS 重定向到专用 1053，本地 `.lan` 名称仍交由原 DNS；原校园认证 DNS 不改变。

当前 LAN 使用 ULA IPv6，经相应有线或 VPS NAT66 出口。原三网模式未把已撤销的无线 IPv6 重新开启，不能把这个模式理解为三路 IPv6 聚合。

## 已验证与限制

- 三模式实际切换后，绑定 Mac 物理 `en0` 的小流量 TLS/HTTP 与 UDP DNS检查完成；隧道普通 LAN 和 1088 均观测到新 VPS IP，单有线两者均为有线 IP，原三网分别观测到有线和 Native 出口。
- 原三网的一次网关 DNS 查询返回 NOERROR 但零答案，外部 DNS 查询有答案；保留该例外，不宣称原 DNS 对所有域名正常。
- 新 IP 隧道实际有三个 MPTCP 子流，物理 LAN ICMP 2/2 通过；路由器源 IPv6 外网 ICMP 2/2 通过并有一个重复响应。本机 `en0` 没有 IPv6 地址，尚未实际验证 IPv6 LAN 客户端完整回程。
- Go race 回归、实际 Linux 隔离 namespace 的 TUN 延迟收包检查，以及路由器 BusyBox 的 8 项隔离 mock 通过。LuCI 静态页面、菜单索引、后端 allowlist RPC 及前端 mock 通过；未在登录后的真实浏览器中逐一点击按钮。
- 本轮没有大文件吞吐测试。此前 128.23Mbps 的一分钟验收属于旧 Web 代理，不能当成新 IP 隧道速度。长期稳定性与整机重启恢复仍待观察。
