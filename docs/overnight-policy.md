# 节假日与周末夜间联网策略

2026-10-05 23:20 GMT+8 已部署到路由器。目标是保留可用网络，学校停网时避免反复认证，并在每天 07:00 检查 Native。时间按路由器 GMT+8 计算，跨午夜重新判断当日。

## 日期与静默

| 日期类型 | 00:06–07:00 行为 |
| --- | --- |
| 普通工作日、官方补班周末 | 静默，停止自动扫描、切换、认证、WAN 恢复与 ECMP 刷新 |
| 官方公布的放假区间、普通休息周六/周日 | 00:06–00:25 保护；随后允许有限故障认证恢复及健康路由维护 |
| 年度清单缺失、损坏或时钟未初始化 | 默认静默；未知年度的周末也不自动放行 |

官方补班日优先于放假标记和星期判断；普通周末由星期计算得出，不必逐一列入清单。寒暑假没有额外自动例外。夜间判断读取本地缓存，不依赖在线 API。

所有日期在 00:06–07:00 都禁止完整扫描、Native 优化比较/切换和无线重启。允许夜间联网的日期也不做定期优化；接口或无线关联消失时保留其他健康链路，待 07:00 恢复白天修复流程。各入口及延迟热插拔任务均重新检查策略。

## 官方清单自动更新

路由器每月 1 日 12:13 检查当年、次年年度通知，不需要 Mac 或 Codex 保持运行。首次启用已实际获取 2026 年清单：33 个放假日、6 个补班日，来源为[中国政府网年度通知](https://www.gov.cn/zhengce/zhengceku/202511/content_7047091.htm)。本轮未检索到 2027 年的精确年度通知，未生成该年清单。

更新器使用中国政府网站内搜索，精确匹配年度通知标题，只下载规定路径的官方 HTTPS 页面。解析器严格校验年度、标题、发布机关、全部节日覆盖、合法日期、跨月/跨年范围及公布天数；不执行下载内容。通过校验后加锁、原子替换，保留上一个有效版本；内容相同则不重复写入闪存。失败保留旧清单并写简短日志，未知年份默认静默。

月度检查足以跟进普通年度安排发布，但不能保证即时发现另发的临时通知，例如[2020 年春节假期延长通知](https://app.www.gov.cn/govdata/gov/202001/27/453442/article.html)。特殊调整需另行核对并使用日期覆盖。官方站点接口或正文格式变化会拒绝更新并保留旧缓存，需要按日志修复解析器。

需要手动刷新时，在路由器白天运行：

```sh
/usr/bin/scut-calendar-update
logread -e scut-calendar
```

更新只处理日历，不认证、注销、扫描或改路由；夜间手动调用同样被拒绝。

## 午夜停网与有限恢复

用户曾观察节假日 00:07 要求重登，登录成功却无公网，00:22 后重登才恢复。00:25 是据此预留缓冲的策略时间，不是学校保证的恢复时刻。

1. **00:06–00:25 保护。** 保留连接和无线关联，不认证、注销、扫描、切换或重启 WAN。00:08、00:23 仅检查公网健康并收敛 ECMP：双路健康保持 1:1，单路失败仅使用健康链路，两路失败移除策略。
2. **00:25 起低频故障恢复。** Native 从 00:25、USB 从 00:27 错峰执行，每条链路约每 15 分钟一次。先复核绑定接口的公网；已在线则不重登。只有已关联接口明确收到指向 `s.scut.edu.cn` 的重定向，且安全会话记录有效，才允许认证。普通超时不触发盲目登录。没有夜间完整扫描或主动优化切换。
3. **认证限制。** 每条链路当日 07:00 前最多两次自动恢复认证，间隔至少 900 秒。尝试前持久记录额度，重启不会重置；超时、登录成功但公网失败也计入次数。旧会话释放失败或不确定时，当夜停止后续认证。原有全局 Portal 锁、两会话保护、精确旧 IP 释放及持久会话记录仍适用。
4. **恢复须有公网证据。** 绑定接口的 HTTPS HEAD 返回 200 才视为在线；夜间主目标失败时使用独立备用 HTTPS 目标复核。登录响应成功本身不能清除故障。额度耗尽后继续低频健康复核，保留可用链路，停止该夜认证；07:00 夜间额度不再阻断白天流程。

无法修复学校统一停网，也不能隔离 Native/USB 同接一个 AP 的共同故障。没有故障时不主动注销或重新登录。

## 每天 07:00 强制检查

定时表保留：

```cron
0 7 * * * FORCE_SCAN=1 /usr/bin/native-watchdog >/tmp/native-watchdog-0700.log 2>&1
1 7 * * * /usr/bin/usb-watchdog >/dev/null 2>&1
2 7 * * * /usr/bin/dualwan-refresh apply >/dev/null 2>&1
```

Native 在正常维护路径上绕过四小时完整比较间隔。先完成现有无线速率、公网检查和必要恢复；前置操作失败可安全返回，因此校园仍断网时不能保证完成比较。强制的是检查，不是无条件切换。现有比较主要依据 RSSI，候选比当前至少强 6 dB 才切换；RSSI 不代表吞吐最佳。切换仍受会话释放、锁、HTTPS 和回滚保护。保留原生 MAC、不固定 BSSID，QCA 维护仍只针对 phy0/phy2 的 MCS7/MCS9。

## 特殊情况手动处理

在路由器执行：

```sh
/usr/bin/scut-night-control status
/usr/bin/scut-night-control quiet
/usr/bin/scut-night-control allow
/usr/bin/scut-night-control clear
```

`quiet` 强制当夜静默；`allow` 临时允许当夜，仍保留午夜保护、次数/冷却及会话安全规则；`clear` 仅移除日期覆盖，恢复日历策略。可以给 `quiet`/`allow` 指定 `YYYY-MM-DD`。

未指定日期时，07:00 前作用于当天，07:00 后作用于次日凌晨；到目标日 07:00 自动失效，文件可保留但不会继续生效。覆盖更新原子替换，并持有全局 Portal 锁避免与认证事务竞态。它不重启无线，也不清空会话记录或认证额度。节假日实际持续停网时可用 `quiet`；非假日临时确认校园供网时可用 `allow`。

## 新关联 RX 初始化宽限（23:31 部署）

QCA 速率维护以驱动 `connected time` 判断本次关联时长；采样开始时不足 15 秒，该轮不依据 RX 低值降档，也不累计/继承 MCS9 升档计时。没有新增睡眠等待。到期后恢复原 RX 判断；时长缺失/无效则不放宽。网关丢包、真实 TX failure、MCS9 上限和公网验证不受影响。适用于 phy0/phy2，包括同 BSSID 重新关联，USB 不受影响。
