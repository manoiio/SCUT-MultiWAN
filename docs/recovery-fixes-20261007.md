# 多 WAN 恢复与 Native 自动选优修复（2026-10-07）

## 现场问题与证据

单有线临时模式已解除。恢复时 radio0 约 −80 dBm，绑定公网检查失败，
网关无响应；默认 DNS 查询也经 radio0，导致实际仍能上网的 USB/有线被
探测为离线。使用临时 `--resolve` 验证这两路 HTTPS 200，刷新 wan1 DHCP
后 Native 恢复。不能据此确定手机登录挤掉了会话。

扫描多次发现 radio2 比 radio0 强约 14–17 dB。日志笼统报告“关联/DHCP
失败”，但 netifd 已记录候选 DHCP lease。仅对不含凭据的 QCA 程序做
诊断，确认一次明确失败为 `qca-phy2-sta0` 的 flock 返回 75。
另一次候选就绪后旧 radio0 无法访问 Portal，精准释放请求 curl7，保护逻辑
保留会话记录并中止。没有为了切换伪造释放或清空记录。

## 已部署修复

* DNS：保留动态 DHCP 上游，在 dnsmasq 中追加绑定有线 `wan` 和 USB
  `phy3-sta0` 的校园 DNS 上游，启用 `allservers`。失效的普通默认出口
  不再阻止健康替代接口进行 DNS 查询。Native 仍使用动态 DHCP DNS，
  无需为当前禁用的 phy0/phy2 持久配置不存在的绑定接口。
  不固定 CDN IP，不替换 LAN DHCP 参数、Mac DNS 或代理配置。
* `native-best`：候选准备复核关联/DHCP；QCA 返回 75 时重试，而不是立即
  宣告 DHCP 失败。最多 25 轮且 45 秒候选阶段截止；每轮重查白天守卫。
  真正的速率命令失败仍拒绝候选。日志区分准备、速率暂缓和错误退出。
* 旧会话释放：先经记录的 Native 接口精准释放记录 IP。若未确认，可经
  已通过 HTTPS 检查的 USB 再确认同一个记录 IP；全程真实 Portal 锁，
  复核记录归属。两路均不能确认时仍拒绝登录。不会释放 USB 的会话 IP。
* `native-watchdog`：只有公网确认失败且网关连续两次无响应，才在白天
  Native 事务/Portal 锁下重新取得 DHCP。至少 5 分钟间隔，保留持久会话
  记录；之后重新验证 HTTPS。普通公网超时、夜间均不能启动此恢复。
* 有线同会话挑战：等待 Portal 锁的上限由 15 秒改为 120 秒，保持单调
  时钟与不可延长的截止时间。重复服务器挑战只更新待处理帧，不延长
  首次等待期限；无锁不回复，不发送新的 EAPOL Start，不改变认证预算。
  这修复了较长 Native 候选准备使有线在 15 秒后退出的问题。

DNS 参数来源：[dnsmasq 官方手册](https://dnsmasq.org/docs/dnsmasq-man.html)。
实际地址来自本设备现有 DHCP/static DNS。参考配置在
`examples/dnsmasq-wan-bound.conf`，安装通过 OpenWrt UCI 修改指定选项，
保留其余 DHCP/DNS 配置。
