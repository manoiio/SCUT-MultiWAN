## 修改范围

只改 Native/USB 四个 `.impl` HTTP 登录、注销入口；有线 EAP/UDP 程序、公共守卫、锁、会话格式、夜间额度、路由、无线维护和 cron 未修改。

每次认证/注销的 curl 增加 `--max-filesize 1048576`，正文上限为 **1 MiB（1048576 字节）**，比此前资源评估中的 64 KiB 建议宽松。无大小可配置环境变量，不允许意外关闭限制。curl 8.4 以后也能限制未知长度响应；本机实际版本 8.22.0 已用合成 HTTP 验证。

读取正文后立即保存 curl 退出码；非零时丢弃捕获的正文，仅记录退出码与“session retained”，返回失败。即使残留正文中已经出现 `result=1`，也不作为完整确认：

- 登录保留请求之前写入的目标会话记录，不自动重试，不增加第二次登录。
- 注销不清空旧会话记录；释放未确认时禁止后续登录。
- 不输出或落盘真实 Portal 正文，不增加新的 Portal 请求。

传输完整且正文未超限时，原来的成功字段检查、公网 HTTPS 验证、释放顺序和返回行为保持。请求 URL、字段、callback、凭据 stdin 方式、接口、TLS 验证、超时与重试策略都保持原样；Native 与 USB 原有的参数差异也保留。没有添加 `--retry`、截断后重新请求、关闭证书验证或缩短超时。

与此前的不同：旧实现会忽略 curl 退出码，因此部分传输失败后，只要已收到的片段包含成功字段，就可能继续或清空会话。现在这类不完整响应按不确定结果保留保护。这是容量限制必需的结果处理，避免“已超限但部分正文被当成功”。
