## 有效参数与限制

测试链路为 `Mac 单 TCP → 路由器临时应用转发 → 三路原生 MPTCP → VPS 合成数据服务`。VPS 单个测试 socket 的 SO_SNDBUFFORCE 请求 4MiB，路由器 MPTCP SO_RCVBUFFORCE 请求 4MiB（Linux 实际计入双倍），Mac 接收缓冲请求 1MiB并绑定 en0。未改全局 TCP 缓冲。

本次较稳的组合是 CUBIC + VPS FQ 每条 TCP 50Mbps，quantum / initial_quantum 为 1448；51Mbps 是略快的短样本。FQ 的 maxrate 是**每条 TCP 流**，不是三路总和，也不是每个校园会话的共享上限；多个下载并发时不能把本次参数直接当成完整生产限流方案。

旧 VPS 最佳本机样本约 132Mbps，新机最佳约 139Mbps，提升约 5%。CPU、RTT 与内核不同，不能从本次对照单独确定改善原因。新机在已测条件下达到约 140Mbps，未达到 300Mbps；更换 VPS 尚未消除三条校园路径各约 50Mbps 的容量现象。精确校园策略、VPS 套餐上行额定值和长期稳定性仍未验证。

若后续用于 115 单连接下载，须另外实现 VPS 侧的 CDN 请求与安全的 MPTCP 传输，并用同一有效链接验证；本轮合成服务、明文临时转发与真实 CDN/加密代理性能不能等同。
